## 2025-05-05 - Fix XSS Array Bypass in escapeHtml and Unescaped JSON in Diagnostics
**Vulnerability:** The `escapeHtml` function could be bypassed by passing an array containing malicious strings instead of a string, allowing XSS execution when the array was implicitly stringified elsewhere without escaping. Also, `qcText` containing JSON stringified values in the diagnostics view was not HTML escaped.
**Learning:** Checking `typeof unsafe !== "string"` and returning `unsafe` unescaped for non-strings allows arrays (e.g. `["<script>"]`) to bypass the filter and later be concatenated into HTML strings as `"<script>"`.
**Prevention:** Enforce string coercion via `String(unsafe)` inside the escape function (after handling null/undefined) to ensure all inputs, including arrays or objects, are correctly stringified and then escaped before returning. Also ensure `JSON.stringify` outputs are explicitly escaped before injection into innerHTML, as stringified JSON can still contain raw HTML characters in values.
