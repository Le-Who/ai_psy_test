## 2024-07-17 - Prevent XSS from untrusted LLM diagnostic output
**Vulnerability:** The application was directly injecting `qcText` (which contains stringified LLM JSON output about quality checks) into the `diagnosticsHtml` via `innerHTML` without escaping. Since this JSON structure is generated by the LLM (an untrusted external source), it was vulnerable to Cross-Site Scripting (XSS).
**Learning:** Even though the variable `qcText` comes from JSON serialization (`JSON.stringify(scaleProfile.qualityChecks)`), stringified objects can still contain unescaped HTML characters (`<`, `>`, etc.) within property values if the LLM generated them. These characters could be interpreted as executable HTML/scripts when injected into the DOM.
**Prevention:** Always sanitize dynamic data originating from external sources (including LLM responses) using `Utils.escapeHtml()` before rendering it into the DOM via template strings or `innerHTML`, regardless of whether it has been stringified as JSON.
